# Roadmap: от текущего шелла к IDE уровня JetBrains

Сопоставление списка фич JetBrains (`~/jetbrains-ide-features.md`) с тем, что
уже есть в этом репозитории, и план разработки по фазам.

**Рамки, заданные заказчиком:**

- Внешний вид — **New UI JetBrains-IDE на базе IntelliJ платформы**
  (GoLand/RustRover/PhpStorm как конкретные референсы), **не Fleet**.
  *(Пересмотрено 2026-08-24 — см. §9; до этой даты действовало обратное:
  «Fleet, не IntelliJ». Фазы **B1**/**B2**, уже смерженные под старое
  требование, переделываются заново под новый вид — см. **B1b**/**B2b**
  в §6.)*
- **Автодополнение кода (любое: basic, smart, postfix, AI/Full Line) — вне
  плана целиком**, не трогаем.
- Начинаем **с редактора**.

Каждая фаза ниже — это один прогон `/dev-chain`, то есть один документ в
`docs/features/`. Роли указаны в порядке слияния из `CLAUDE.md`
(`rust-core-dev` → `rust-lsp-dev` → `rust-ui-dev`), `hacker` отмечен там,
где диff заведомо трогает security-sensitive путь.

Оценка объёма: **S** — один прогон без сюрпризов, **M** — крупный диф в
двух крейтах, **L** — многодневная веха, **XL** — веха, которую имеет смысл
дробить на подфазы уже по ходу.

## 1. Что есть сейчас (инвентаризация)

`ide-core` (~3.6k строк)

| Модуль | Что умеет |
|---|---|
| `buffer.rs` | `String` + `Option<PathBuf>`, insert/delete по байтовым offset'ам, undo/redo стеком одиночных `Edit`, save/save_as, лимит на размер открываемого файла |
| `project.rs` | открыть/создать каталог как проект, рекурсивный скан дерева (`DirEntry`) |
| `search.rs` | `search_tree` — plain-text поиск по дереву, лимиты на размер файла и число результатов |
| `syntax.rs` | ручной токенайзер: 19 языков, 11 `TokenKind`, lookup по расширению/имени/префиксу имени, лимит подсветки 2 МБ |
| `language.rs` | список `(name, extension, command)` для запуска языковых серверов |
| `git/mod.rs` | детект репозитория, diff файла против HEAD, diff коммита, граф коммитов, 3-way конфликты + запись резолва в индекс |

`ide-lsp` (~1.8k строк) — клиент на tokio, stdio, LSP-фрейминг; ровно 4
запроса: `didOpen`/`didChange`/`didClose`/`references`; события:
`publishDiagnostics`, `references`, ошибка сервера. Конвертация
позиций byte↔UTF-16.

`ide-ui` (~4.3k строк) — `egui`/`eframe`; три панели (дерево / редактор /
Claude), нижняя панель с 4 вкладками (Problems, Cargo Output, Usages,
Search), окна «Languages…», Usages-popup, confirm-модалка; тёмная/светлая
тема тумблером; cargo-панель (Build/Run/Test/Check/Clippy) со стримом
вывода; git-панель; Claude-панель через внешний CLI.

**Редактор сегодня** — это `egui::TextEdit::multiline` над `String`-скретчем;
после каждого кадра `diff_replace` вычисляет одну вставку/удаление и
применяет её к `Buffer`, токены пересчитываются по всему файлу. Из этого
следуют все ограничения раздела 3.

## 3. Два архитектурных блокера

Прежде чем брать фичи по списку, нужно снять два ограничения. Почти каждая
строка раздела 2.1 упирается в них, и делать их «потом» будет означать
переписать всё, что успеет на них налипнуть.

### 3.1 `TextEdit::multiline` — тупик

Сейчас редактор — это стандартный виджет egui над `String`. У него:

- **один курсор и одно выделение** → мультикурсоры невозможны в принципе;
- **нет гуттера и нет доступа к геометрии строк** → нет номеров строк,
  folding-стрелок, breakpoint'ов, git-маркеров, лампочки Alt+Enter,
  маркеров на скроллбаре;
- **`LayoutJob` на весь файл каждый кадр** (`render.rs:332-351`) → файл на
  10k строк раскладывается целиком на каждом кадре; отсюда и лимит
  подсветки 2 МБ;
- **нет вставки не-текстовых элементов в поток строки** → инлей-хинты и
  свёрнутые регионы («`{…}`») нарисовать некуда;
- **редактирование восстанавливается диффом** (`app.rs:176 diff_replace`) —
  эвристика «одна вставка или одно удаление за кадр»: она в принципе не
  может выразить мультикурсорную правку, а undo-стек `Buffer` из-за неё
  наполняется посимвольными записями без группировки.

→ **фаза A2: собственный виджет редактора.** Это переписывание, а не
доработка, и это самая крупная и самая рискованная фаза плана. Её нужно
делать рано (сейчас), пока на `TextEdit` завязано мало кода.

### 3.2 `Buffer` — модель текста без строк, курсоров и транзакций

`Buffer` хранит `String`, знает только байтовые offset'ы и одиночные
`Edit`. Нет индекса строк (каждый перевод `(line, col) ↔ offset` — линейный
проход), нет курсоров, нет транзакций, нет группировки undo, нет
инкрементального ретокенайза.

→ **фаза A1: текстовый движок.** Делается первой, в `ide-core`, без UI —
что удобно: 100% покрывается юнит-тестами до того, как появится виджет.

## 4. Внешний вид (superseded 2026-08-24 — историческая версия)

**Это первоначальная версия раздела, писавшаяся под Fleet-требование.**
Она реализована фазами **B1**/**B2**, которые уже смержены в `main`. С
2026-08-24 действует противоположное требование — см. §4b (актуальная
версия) и §9 (протокол решения). Раздел ниже оставлен как есть, для
истории и чтобы **B1b**/**B2b** знали, что именно переделывают —
построчные ссылки на `render.rs` из этой версии устарели (в исходном виде
эти строки относились к коду *до* B1/B2).

<details>
<summary>Исходный текст (Fleet)</summary>

Fleet — это не «IntelliJ с другой темой», а другая философия оболочки.
Конкретные решения, которые копировали:

1. **Минимальный хром.** Никаких панелей с кнопками-рамками. Тулбар — тонкая
   полоса с иконками без границ.
2. **Единый верхний бар:** слева — имя воркспейса и навигация назад/вперёд,
   в центре — «контекстная» строка с путём/именем файла (она же — точка
   входа в Search Everywhere), справа — индикаторы (Smart Mode, проблемы,
   ветка git).
3. **Smart Mode** как переключаемый режим языковой интеллектуальности
   (тумблер off / starting / on / error).
4. **Плотный slim-tree** слева: маленький отступ, иконки по типу файла, без
   «жирных» `CollapsingHeader` egui.
5. **Тонкие табы** без крестика-кнопки на каждом (крестик — по ховеру).
6. **Статус-бар снизу**: `line:col`, кодировка, перевод строки, отступ,
   счётчики ошибок/предупреждений, ветка.
7. **Палитра команд** (Cmd+Shift+K / Go to Action) как основной способ
   добраться до чего угодно.
8. **Палитра цветов** Fleet Dark / Fleet Light: почти-нейтральные серые
   (фон ≈ `#18181A`), один синий акцент.
9. **Шрифты**: Inter (UI) + JetBrains Mono (код), вшитые в бинарник.

</details>

## 4b. Внешний вид (актуально с 2026-08-24): что берём у IntelliJ New UI

Референсы — GoLand / RustRover / PhpStorm на New UI (2023.1+). В отличие
от Fleet, IntelliJ-платформа — это **классическая модель докинга
тул-виндов** с видимым хромом, а не «минимальный хром без рамок». Ниже —
то, что конкретно копируем, пункт за пунктом соответствует старому
списку в §4, чтобы было видно, что именно меняется:

1. **Видимый хром тул-виндов вместо минимального.** Каждое тул-окно —
   собственная рамка/панель с заголовком (название, иконка «свернуть»,
   иногда gear-меню), а не безрамочная плашка. Разделители (`splitter`)
   между тул-окнами и редактором — тонкие, но видимые линии, а не просто
   отступ.
2. **Тул-виндовые полосы по краям вместо единого верхнего бара.** Слева —
   вертикальная полоса с подписанными иконками (Project, Structure,
   Bookmarks…), снизу — горизонтальная (Problems, TODO, Version Control,
   Terminal, Services…), справа — вертикальная (Notifications и т.п., у
   нас пока не занята). Клик по иконке открывает/закрывает/докает окно;
   двойной клик по заголовку окна — «maximize». Это заменяет Fleet-овскую
   единую верхнюю полосу с контекстной строкой.
3. **Главный тулбар (New UI)**: одна строка сверху редактора/окон —
   слева навигация (back/forward, Search Everywhere), по центру — выбор
   run-конфигурации + Run/Debug/Stop, справа — VCS-виджет (текущая ветка),
   Settings, уведомления. Не «контекстная строка» Fleet, а классический
   IntelliJ main toolbar.
4. **Smart Mode остаётся функционально** (тумблер off / starting / on /
   error), но визуально переезжает в статус-бар как обычный виджет —
   IntelliJ не выделяет языковую интеллектуальность отдельным
   UI-элементом в верхнем баре, у него просто есть индексация/статус
   сервиса в статус-баре.
5. **Project tool window** вместо slim-tree: стандартная плотность строк
   IntelliJ-дерева (не ультра-компактная, как у Fleet), иконки по типу
   файла, контекстное меню, но заголовок и рамка — как у тул-окна (см.
   п.1), а не голое дерево в сайдбаре.
6. **IntelliJ-табы редактора** вместо тонких Fleet-табов: прямоугольные
   табы с подсветкой верхней грани активного, крестик-закрытие по ховеру
   (в New UI по умолчанию скрыт до наведения — как и было, не меняется),
   индикатор «грязного» файла точкой — остаётся как есть.
7. **Статус-бар** — тот же набор данных (`line:col`, кодировка, перевод
   строки, отступ, счётчики ошибок/предупреждений, ветка), но
   IntelliJ-визуальный язык: иконка+текст виджеты, разделённые тонкими
   вертикальными чертами, сюда же переезжает индикатор Smart Mode (п.4).
8. **Палитра команд** (Search Everywhere `⇧⇧`, Find Action `⌘⇧A`) —
   без изменений: она уже IntelliJ-формы (сделана в **B3**/**C2** по
   JetBrains-биндингам), Fleet-пивот её не затрагивает.
9. **Палитра цветов**: IntelliJ Darcula (тёмная) и IntelliJ Light New UI
   (светлая) вместо Fleet Dark/Light. Ключевое структурное отличие от

## 5. Хоткеи: дефолт — JetBrains macOS, с возможностью правки

**Требование (согласовано):** раскладка по умолчанию — keymap **«macOS»
из IntelliJ-based IDE** (не «macOS System Shortcuts», не Fleet-раскладка), и
она **полностью редактируемая**.

### 5.1 Как это устроено

- **Единственный источник правды — реестр команд (`B3`).** Каждая команда:
  `id`, заголовок, категория, `enabled`-предикат и **дефолтный биндинг из
  JetBrains macOS**. Ни одна фича после B3 не имеет права читать
  `ctx.input(|i| i.key_pressed(...))` у себя — иначе биндинг нельзя ни
  переназначить, ни показать в палитре, ни проверить на конфликт. Сейчас
  так и сделано (`render.rs:190-231` — шесть хардкоженных проверок), и
  именно это B3 разбирает.
- **Правка — фаза `G2`, поднята в очереди сразу за B3.** Оверлей
  пользовательских биндингов поверх дефолтов, конфликты видны при
  назначении, сброс к дефолту, экспорт/импорт, пресеты-схемы (JetBrains
  macOS — дефолт, плюс Fleet и VS Code как альтернативы).
- **Кроссплатформенность.** `egui::Modifiers::command` уже абстрагирует
  Cmd/Ctrl, `Modifiers::alt` — Option/Alt, поэтому одна запись покрывает и
  macOS, и Windows/Linux. Но JetBrains-раскладки для macOS и Win/Linux
  расходятся не только модификатором (Quick Doc: `F1` против `Ctrl+Q`;
  Delete Line: `⌘⌫` против `Ctrl+Y`), поэтому биндинг в реестре — это не
  одна запись, а `{ mac, other }`, где `other` по умолчанию выводится из
  `mac` заменой модификаторов, а расходящиеся случаи задаются явно.
- **Два механизма, которых у egui нет из коробки:** **double-tap** (`⇧⇧` —
  Search Everywhere, `⌥⌥`+стрелка — клонирование курсора) и
  **аккорды/префиксы** (`⌃T` → буква для Refactor This). Без них часть
  дефолтной раскладки нереализуема. Минимальный детектор double-tap
  появляется раньше, в **A3** (он нужен там для `⌥⌥`+стрелки), **G2**
  обобщает его до части реестра и добавляет аккорды.

Первые десять — жёсткая последовательность, дальше два трека идут

`G2` идёт девятой, а не в хвосте: она нужна ровно в тот момент, когда
биндингов становится больше десятка, и она же приносит double-tap и аккорды,
без которых `⇧⇧` (Search Everywhere, №15) и `⌥⌥`+стрелка (A3) не сделать.

Три реперные точки, по которым удобно мерить прогресс:

- **после №3** — редактор перестаёт быть текстареей: номера строк, гуттер,
  большие файлы, кадры без просадки;
- **после №10** — набирать код в этой IDE становится комфортно (отступы,
  скобки, мультикурсоры, поиск в файле, фолдинг) и она выглядит как Fleet;
- **после №13** — Alt+Enter работает, и дальше рефакторинги идут потоком,
  потому что все они — надстройки над одним движком `WorkspaceEdit`.

## 8. Решения по платформе (согласовано 2026-08-17)

Все пять открытых вопросов закрыты; `CLAUDE.md` уже приведён в
соответствие, отдельного согласования по ходу фаз не требуется.

1. **Git remote — разрешён.** Формулировка «no remote/network operations in
   v1» снята. Сетевой ввод-вывод в `ide-core` ограничен ровно git-remote
   операциями через `git2` — ничто другое в крейте сокет не открывает. В
   список security-sensitive путей к `crates/core/src/git/**` добавлены

   данными от remote как с враждебными. Уже смерженный git-код остаётся
   локальным, пока доку явно не скажет иное.
2. **Отладчик — отдельный крейт и отдельная роль.** В цепочке теперь 4
   роли: core → lsp → **dap** → ui. Заведён
   `.claude/skills/rust-dap-dev/SKILL.md`, крейт `crates/dap` создаёт первый
   прогон, которому он нужен (роль имеет право добавить свою строку в
   `workspace.members` — единственное исключение из «не трогай чужие
   пути»). `crates/dap/**` внесён в security-sensitive пути: спавн
   адаптера и отлаживаемой программы, `evaluate` исполняет выражения в
   debuggee, ответы адаптера — недоверенный ввод.
   **Мультиязычность зафиксирована как жёсткое правило скилла**, а не как
   пожелание: ни языка, ни бинарника адаптера, ни его launch-схемы в коде
   крейта; адаптер — из конфига, launch/attach-аргументы — насквозь
   непрозрачным JSON, фичи — по капабилитям из `initialize`.
   Адаптер-специфичные обходы допускаются только как таблица по id
   адаптера, не как `if adapter == …` в логике.
3. **Новые shell-out поверхности внесены в security-sensitive пути:**
   терминал/PTY (**F2**), run-конфигурации (**F1**), внешний форматтер
   (**A9**). `hacker`-пасс на этих фазах обязателен.
4. **Зависимости одобрены** — в `CLAUDE.md` появился раздел «Dependencies»

5. **Раскладка клавиш — JetBrains macOS по умолчанию и редактируемая.**

## 9. Отказ от Fleet-вида в пользу IntelliJ New UI (согласовано 2026-08-24)

**Решение (пользователь, в этом чате):** внешний вид меняется с JetBrains
Fleet на **New UI JetBrains-IDE платформы** (GoLand/RustRover/PhpStorm —
конкретные референсы, New UI ветка 2023.1+, не Classic UI). Это **полный
пивот**: не только докинг тул-виндов, но и хром/цвета/тулбар/меню —
описание см. §4b, которое заменяет §4 как источник истины для внешнего
вида идущего вперёд (§4 сохранена как исторический контекст).

Причина смены зафиксирована как есть: прямой запрос пользователя,
без дополнительного бизнес-обоснования — предыдущее Fleet-требование
(§1, до правки) действовало с момента основания проекта и было
реализовано фазами **B1**/**B2**; правка не отменяет факт, что эти фазы
были смержены и прошли `rev`/тесты под тогдашнее требование, она вводит
новое требование, под которое B1/B2 переделываются заново (**B1b**,
**B2b** — §6, трек B).

**Что не меняется:**

- Раскладка клавиш — по-прежнему JetBrains macOS keymap (§5), она никогда
  не была завязана на Fleet (Fleet и раньше был референсом только для
  внешнего вида, не для биндингов — см. историческую формулировку в §4,
  п.9 списка и `CLAUDE.md`).
- Палитра команд / Search Everywhere (**B3**/**C2**) — уже сделаны в
  IntelliJ-форме, пивот их не касается.
- Собственный виджет редактора (**A2**) — геометрия, курсоры, ввод,
  viewport culling не переделываются; меняются только токены, которые он
  читает (**B1b**), и панели вокруг него (**B2b**), не сам виджет.
- Всё, что не является «панелями/хромом»: LSP-функциональность,
  рефакторинги, git-модель и т.д. — без изменений.

**Обновлённые документы:** `CLAUDE.md` (раздел «Look and feel», две
Fleet-ссылки в «Dependencies»/«Keyboard shortcuts»), этот файл (§1, §4→§4b,
§6 трек B, §7). Формальные feature-документы для самого редизайна —
